# Release notes — 1.0.0-rc.2

**Tagged:** 22 November 2026 · **Signed-off commit:** the tag itself · **Predecessor:** `v1.0.0-rc.1` on `88e67ac`

This candidate does not add a feature to the booking journey. It closes the three things that stood
between `rc.1` and a release anyone could defend: an account that could not be suspended, a retention
period that contradicted its own decision, and a backup that could not be restored.

## What changed

**Access revocation — a suspension that keeps the record (`54ed855`).** Until now an account could be
created and never removed: there was no `user:delete` and no way to stop one being used. `user:deactivate`
and `user:reactivate` now exist behind `users.manage`, written as one transaction that flips
`users.state`, appends an `audit_events` row, and bumps `auth_version` — which invalidates every session
that account holds in a single statement rather than waiting for cookie expiry. The last active
administrator cannot be suspended, and the check is not a phantom: it counts, it refuses, and
`ChangeUserAccessTest` pins it.

**Retention is seven years, not five (`b7de280`).** `Config::DEFAULT_RETENTION_DAYS` was `1827`; the
Ethiopian medical record-keeping directive that DEC-2026-11-20-02 approved says seven, so the constant is
now `2557` — the larger figure, because the span can hold two leap days and a shorter window would end
before the period the privacy notice states. `RetentionWindowTest` pins the constant, the sample
environment, and the worst-case span. The change is forward-only: rows already redacted are not restored,
and nothing is retroactive.

**The dump can be restored (`fea33e4`).** `published_content.live_key` is a generated column, `SELECT *`
expands to generated columns, and the INSERT therefore named it — which MariaDB refuses (error 1906). The
restore drill had been restoring 29 of 51 tables and stopping, so every hourly dump since 20 November was
unrestorable while `db:backup` reported success. The column list now comes from `SHOW FULL COLUMNS` minus
`STORED GENERATED` and `VIRTUAL GENERATED`; `DEFAULT_GENERATED` is kept deliberately, because it marks an
ordinary column with an expression default. `BackupGeneratedColumnsTest` covers all four cases.

**Documentation that is now true (`6684fb5`, `dc2e414`).** UAT fixture data, the UAT scope boundary
(delivery to an inbox is out of scope while `NOTIFY_DRIVER=log`), and the host accounts — databases,
users, where each password lives, and the deploy key fingerprint — without a secret in the repository.

## What this candidate does not contain

- **No policy-page content.** Nine bracketed values remain unfilled, `/privacy` has no effective or
  review date, and BL-A1 has an approval but no text. The publish path refuses those pages, correctly.
- **No notification delivery.** Staging runs `log`; the Brevo key is empty by design.
- **Twelve ADRs remain "Implemented, unapproved".** The code ships; the governance record does not cover
  it yet.
- **No production cutover.** `booking.hakimerad.com` is untouched. ADR-018 still says production release
  is not authorised.

## Deploy note

This candidate was published to staging by fetching the tagged tree on the host and copying the ten
changed runtime files, because no FTP credential and no SSH port were available on 22 November. The
snapshot for rollback is `releases/20261122-*-prev`. That is a deviation from `deploy.sh`'s artifact flow
and is recorded in `outputs/status-and-plan-2026-11-18-r2.md` §26, not presented as the normal path.
